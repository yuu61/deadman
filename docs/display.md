## 列

| 列 | 内容 |
| --- | --- |
| HOSTNAME | 設定に書いた名前 |
| ADDRESS | IP アドレスは短い標準表記、ホスト名は設定に書いた表記。構築エラーの行は入力表記。direct / quic / ssh / netns / vrf のホスト名で送信するファミリーが固定されている場合は、`google.com [IPv4]` / `google.com [IPv6]` のように併記 |
| VIA | 監視方式と、行を見分ける詳細。tcp はポート、quic はポート 443 なら `QUIC`、それ以外は `QUIC 8443` のようにポートを併記。nexthop はゲートウェイ、中継する方式は中継先・名前空間名・VRF 名（`ssh jump` など）。構築エラーの行は `error` |
| LOSS | 損失率（%）。FAIL ÷ SNT |
| RTT | 最新のプローブの RTT。応答の無かったプローブや観測できなかったプローブの後は 0 |
| AVG | 応答したプローブの RTT の平均 |
| MIN / MAX | 応答したプローブの RTT の最小 / 最大 |
| JIT | ジッタ。応答の続いたプローブどうしの RTT の差を、RFC 3550 と同じ 1/16 の指数移動平均でならした値。間の失敗は飛ばす |
| SNT | 対象を観測できたプローブの数（`t` / `s` / `?` は数えない） |
| FAIL | 応答の無かったプローブの数（`X` の数） |
| RESULT | 結果の履歴（[RESULT バー](#result-バー)） |

- RTT / AVG / MIN / MAX / JIT はミリ秒です。小数点以下の桁数は `p` キーか `precision` で変えます。
- ADDRESS のファミリー表示は `resolve_family` または送信元アドレスから確定した値です。TCP のホスト名は省略時も `[IPv4]` を表示します。ファミリーを固定していない他の方式のホスト名や、IP アドレス、構築エラーの行には付けません。長いホスト名は短縮しても `[IPv4]` / `[IPv6]` は残します。
- RESULT 以外の列は、キー（`m` / `v` / `h` / `a`）か `columns` ディレクティブで隠せます。`m` は MIN と MAX をまとめて切り替えます。
- 統計と履歴は `r` でリセットします。再読み込みでは、[行の同一性](configuration.md#行の同一性)が同じ行は統計と履歴を引き継ぎます。

## 監視の進み方

- **既定**: 上の行から 1 行ずつ順にプローブを送ります。結果が返ってから 50 ms 後に次の行へ進み、全行が終わると 1 秒待って次の巡回を始めます。矢印が送信中の行を指します。
- **async モード（`-a`）**: 全行に同時にプローブを送り、巡回を 1 秒ごとに始めます。最も遅いプローブが 1 秒を超えたときは、それが終わってすぐ次の巡回を始めます。送信中の行に矢印を付け、`-b` で点滅させます。

1 回のプローブの待ち時間は方式によって異なります（[プローブの待ち時間](platform.md#プローブの待ち時間)）。

## RESULT バー

RESULT バーは、1 回のプローブを 1 文字で、左を最新として並べます。
履歴は行ごとに最大 256 件を保ち、端末の幅に入る分を表示します。端末を広げると、隠れていた古い結果が現れます。

### 失敗の文字

| 文字 | 意味 | LOSS / SNT / FAIL | ログの状態 |
| --- | --- | --- | --- |
| `X` | 送ったプローブに応答が無い（損失） | 数える | `down` |
| `t` | 中継（ssh・SNMP エージェント・RouterOS API）が時間内に応答しない | 数えない | `unknown` |
| `s` | 中継に接続できない・拒否された・結果以外を返した | 数えない | `unknown` |
| `?` | 監視元の側で失敗し、対象を観測できなかった（経路が無い、ICMP ソケットを開けない、宛先名を解決できない、`ssh` / `ip` が無い、名前空間 / VRF が無い、QUIC の TLS 検証に失敗した、など） | 数えない | `unknown` |

`t` / `s` / `?` は対象の死活が分からなかったプローブなので、損失にも成功にも数えません。
方式ごとの分類は [設定ファイル](configuration.md#監視方式) の各方式の説明にあります。
構築エラーの行は、RESULT 欄の先頭に動かない `X` を 1 つ置き、その後ろに理由を表示します。

### 文字の組

応答したプローブは、RTT の段階を表す文字で描きます。文字の組は `-g`、`glyph` ディレクティブ、`b` キーで選びます。

| 組 | 文字 | 段階 |
| --- | --- | --- |
| `block` | `▁▂▃▄▅▆▇█` | 8 段階。段 i は scale×i 以上 scale×(i+1) 未満、`█` は scale×7 以上 |
| `ascii` | `_.-=+*#@` | `block` と同じ 8 段階・同じ境目で、文字だけを ASCII にしたもの |
| `digit` | `0`〜`9` | 10 段階。数字 d は scale×d 以上 scale×(d+1) 未満、`9` は scale×9 以上（scale 10 なら `3` は 30〜39 ms） |
| `auto` | `block` か `ascii` | 起動時に端末を判定し、ブロック文字を表示できなければ `ascii` を使う（既定） |

- scale は `-s`、`scale` ディレクティブ、`↑` / `↓` キーで変えます。キーは 0.01 / 0.02 / 0.05 / 0.1 / … / 50 / 100 ms の段を順に移ります。
- `l` キーで対数表示に切り替えます（線形 → e 倍 → e² 倍 → 線形）。対数表示では、段 i が scale×aⁱ 以上 scale×a^(i+1) 未満を受け持ちます（a は e か e²）。最も低い段は scale×a 未満のすべて、最も高い段（`█` / `@` / `9`）はその上のすべてです。
- 文字の色も同じ段階で決まります（[RESULT バーの色](#result-バーの色)）。

### `auto` の判定

`auto` は次のどちらかに当てはまると `ascii` を選び、どちらにも当てはまらなければ `block` を選びます。

- ロケール（`LC_ALL` → `LC_CTYPE` → `LANG` のうち、最初に設定されている値）が UTF-8 でない（例: `C`、`ja_JP.eucJP`）。何も設定されていない場合と Windows では判定しません。
- Linux の仮想コンソール（tty1 など）で実行しており、読み込まれているコンソールフォントに `▁`〜`█` のどれかが無い。カーネルからフォントの Unicode 表を取得して確かめます。Debian 系の既定フォント Lat15 が該当します。

SSH、端末エミュレータ、tmux、fbterm などの疑似端末（pty）では、実際の描画は接続元の端末のフォントが行うため判定できず、`block` のままです。
**Linux コンソールから SSH で別ホストの deadman を開く**場合は、`-g ascii` か `glyph ascii` を指定してください。

## RESULT バーの色

応答したプローブは、段階に応じて色分けします。
最も速い段階がシアン（青緑）、途中が黄、最も遅い段階（`█` / `@` / `9`）が橙で、その間は段階ごとに少しずつ変わります。
scale・対数表示・文字の組を変えると、色の境目も変わります。
失敗（`X` / `t` / `s` / `?`）は、赤地に白い文字で塗りつぶします。

| 意味 | 色 | 値（24 ビット） |
| --- | --- | --- |
| 安全 | シアン | `#00AAAA` |
| 注意 | 黄 | `#FFF100` |
| 警戒 | 橙 | `#FF8000` |
| 失敗 | 赤地に白 | `#E72300` の地に `#FFFFFF` |

環境変数 `NO_COLOR` を設定すると、色を付けません（失敗の塗りと、[行の強調](#行の強調)の太字・下線も付けません）。

### 端末ごとの色

実際の色は、端末の色数と背景の明暗に合わせて選びます。

- **24 ビットカラー**（`COLORTERM=truecolor` などを設定する端末）: 上の表の色と、その間のグラデーションです。
- **256 色**（`TERM=xterm-256color` など）: 256 色パレット（16〜255 番）のうち、背景に対してコントラスト比 3:1 以上ある最も近い色です。明るい背景では、白地で 3:1 を満たす暗い黄が少ないため、隣り合う段階が同じ色になることがあります。
  - SSH で `COLORTERM` が転送されるのは、クライアントの `SendEnv` とサーバーの `AcceptEnv` の両方に含まれる場合だけです。転送されなければ、24 ビットカラーに対応した端末でも、SSH 越しでは 256 色で表示します。
- **16 色**（Linux の仮想コンソール、`TERM=xterm` など）: 色合いは端末の配色設定に従います。
  - 16 色には橙が無いため、速い側をシアン、中央を黄、最も遅い側を通常の黄で表します。
  - 暗い背景では、注意に明るい黄を使います。通常の黄は、Linux コンソールでは茶色（`#AA5500`）に、ほかの多くの端末では明るい黄より暗い黄に見えるため、最も遅い側だけに使います。明るい背景では、明るい黄が白地で見えにくいため注意にも通常の黄を使い、最も遅い側と同じ色になります。
  - 失敗は、赤地（通常の赤）に明るい白の文字です。Linux コンソールの赤地（`#AA0000`）は黒地に対して 2.7:1 と 3:1 に届きませんが、セル全体を塗るので読み取る必要がなく、文字と赤地のコントラスト比は 7.8:1 あります。
  - Linux コンソールの背景色は 8 色（0〜7 番）だけで、明るい背景色は通常の色として表示されます。黄の背景は茶色になるため、段階の色には背景を使いません。
- **明るい背景**: 起動時に端末へ背景色を問い合わせます。背景が明るい場合は、遅い段階ほど暗くした色を使います。最も速い段階で白地に対するコントラスト比 3:1（WCAG 2 の非テキストの基準）、最も遅い段階で 4.5:1 とし、その間は明るさが均等に変わります。一律に 3:1 まで暗くすると段階の明るさがそろい、1 型・2 型色覚では段階を見分けにくくなるためです。問い合わせに応答しない端末や、tmux / screen の中では、暗い背景として扱います。

### 配色の根拠

- **色の意味**: 黄 = 注意、赤 = 危険という対応と、4 段階以上は赤と緑の間の色で表すという方針は、ISO 22324（色による警報の指針）に従っています。安全は ISO 22324 の緑から、色覚の多様性に配慮して青寄りのシアンにずらしています（次項）。
- **色覚の多様性**: 1 型・2 型色覚では赤と緑の軸が失われ、青と黄の軸と明るさで色を見分けます。
  - 緑は黄や橙と同じくくすんだ黄色に寄って見えるため、安全を緑にすると、最も速い段階と最も遅い段階が近い色になります。カラーユニバーサルデザイン（CUD）推奨配色セット ver.4 の青寄りの緑 `#03AF7A` でも、1 型色覚のシミュレーション（Machado ら 2009、重度 1）で Oklab の色差は 0.093 です。シアンは青の成分を持つので、両端の色差は 0.159 に広がります。
  - 16 色の緑と黄は、1 型・2 型色覚ではどちらも黄色に見え、ほとんど見分けられません（Linux コンソールの明るい緑と明るい黄は、1 型色覚のシミュレーションで Oklab の色差 0.03）。安全のシアンは、この点でも緑より適しています。
- **値の選び方**:
  - シアン `#00AAAA` は Linux コンソールのシアンと同じ色で、16 色の端末でも同じ色になります。
  - 黄は CUD 推奨配色セット ver.4 の値です。この配色セットは、JIS Z 9103:2018（安全色）の改正にも協力した CUDO によるものです。
  - 橙は、sRGB で赤と黄の中間の `#FF8000` です。ver.4 のオレンジ（`#F6AA00`）は黄に寄っているため、256 色の端末では最も遅い 2 段階がどちらも 214 番（`#FFAF00`）になり、遅い側が目立ちません。`#FF8000` は 256 色では 208 番（`#FF8700`）の橙になります。
- **失敗の塗り**: 失敗はセルを赤で塗りつぶし、白い文字を載せます。
  - 塗りのあるセルは失敗だけなので、色覚によらず、色でなく形で段階と見分けられます。塗らずに赤の文字で表すと、明るい背景の 2 型色覚では、最も遅い段階の橙とほぼ同じ色になりました。
  - 赤地に白は、安全標識で赤と組み合わせる対比色です。
  - 塗りの色は、CUD 推奨配色セット ver.3 の赤（`#FF2800`）を、白い文字とのコントラスト比が 4.5:1（WCAG 2 の文字の基準）になるまで暗くした `#E72300` です。256 色では 160 番（`#D70000`）の地に 231 番（`#FFFFFF`）で 5.4:1 です。
  - 塗りは黒地と白地のどちらに対しても 3:1 以上あるため、背景の明暗によらず同じ色を使います。端末の赤を使わずに値を指定しているのは、配色設定によっては赤が橙になる（Solarized など）ためです。
- **補間**: 中間の色は、知覚的に均等な色空間 Oklab で基準の 3 色を結ぶ道のりを、色差が等しくなるように等分しています。基準の色ごとに等分すると、黄を挟む 2 段階がほぼ同じ色になるためです。
- **色だけに頼らない**: 段階は文字の高さ（数字表示なら数字）でも読み取れます。

## 行の強調

RESULT バーの左側（矢印からホスト名・統計列まで）は、ホストの状態に応じて強調します。

| 状態 | 表示 |
| --- | --- |
| 最新のプローブが応答していない（`X` / `t` / `s` / `?`）、またはまだ結果が無い | 行を太字 |
| 応答している。ただし表示中の RESULT バーに失敗が残っている | ホスト名に下線 |
| 応答している。表示中の RESULT バーに失敗が無い | 強調なし |

- 下線は、応答が戻ったばかりのホストや、ときどき応答が途切れるホストを見つけるための、太字より控えめな印です。
- 下線の判定に使うのは、RESULT バーに表示している範囲だけです。応答が続いて失敗がバーの右端から押し出されると、下線は消えます（端末を広げてバーが伸びれば、また現れることがあります）。`r` で統計をリセットした場合も消えます。
- HOSTNAME 列を隠している場合は ADDRESS に、ADDRESS も隠している場合は VIA に下線を付けます。
- 太字の見え方は端末によって異なり、太い書体で表示するものと、明るい色（白など）で表示するものがあります。下線はそのどちらとも別の手がかりなので、色数・背景の明暗・色覚によらず太字と見分けられます。
- 構築エラーの行も太字です。

## 画面上部の警告

監視の行の上に、次のような警告を 1 件 1 行で表示します。

- 設定の書式: 閉じていない引用符、アドレスの後の `=` を含まない語
- 構築エラーの行の数（理由は各行の RESULT 欄）
- 直接 ICMP / nexthop のソケットを開けない（Linux では対処方法の行が続く）
- strict な rp_filter（[動作環境と権限](platform.md#rp_filter)）
- 非推奨の `probe=snmp` を使っている対象
- 再読み込みで設定を読めなかった（それまでの監視を続ける）
- 使えない `-s` / `-c` の値を無視した
- ログの取りこぼしと書き込みの失敗（[ログ](logging.md)）

警告は、ほかの見出し行を除いた高さの半分までに収め、監視の行を画面から押し出しません。
収まらない分は、最後の行に件数を表示します。
設定についての警告は、再読み込みのたびに読み直した内容に置き換わります。

## コンソールフォント

RESULT バーのブロック文字（`▁▂▃▄▅▆▇█`）を表示するため、Unicode に対応した端末（Windows Terminal など）を推奨します。
SSH 経由では接続元の端末のフォントで表示します。
Linux の仮想コンソール（tty1 など）に直接表示する場合は、フォントの収録字数が限られるため、ブロック文字が欠けたり `#` のように崩れたりすることがあります。

deadman はこれを起動時に判定し（[`auto` の判定](#auto-の判定)）、ブロック文字の無いフォントでは RESULT バーを ASCII で表示します。
数字表示（`-g digit` / `b` キー）も ASCII だけで描けるので、同じように使えます。

ブロック文字のまま表示したい場合は、次のどちらかでフォントを差し替えてください。
コンソールフォントを差し替えると、`auto` もブロック表示を選びます。
fbterm は疑似端末なので判定の対象外で、ブロック表示になります。

### fbterm と Source Han Sans（推奨）

`/dev/tty1` などの HDMI 側の仮想コンソールで実行する場合は、framebuffer 上で OTF を描画できる `fbterm` が最も確実です。

```console
# Source Han Sans を導入する
mkdir -p ~/.local/share/fonts/source-han-sans
curl -L -o /tmp/source-han-sans.zip \
  https://github.com/adobe-fonts/source-han-sans/releases/latest/download/01_SourceHanSans.ttc.zip
unzip -o /tmp/source-han-sans.zip -d ~/.local/share/fonts/source-han-sans
fc-cache -fv

# fbterm をインストールして起動する（-s はフォントサイズ）
sudo apt install fbterm
fbterm -n "Source Han Sans" -s 32
./deadman deadman.conf
```

一般ユーザーが `/dev/fb0` にアクセスするには、`video` グループに追加してください（`sudo usermod -aG video "$USER"`）。

### コンソールフォントの差し替え（簡易）

`fbterm` を使えない環境では、仮想コンソールのフォント自体を差し替えます。

```console
sudo apt install psf-unifont
sudo setfont /usr/share/consolefonts/Unifont-APL8x16.psf.gz
```

永続化するには、`/etc/default/console-setup` に次を設定し、`sudo setupcon --font-only` で反映します。

```ini
CHARMAP="UTF-8"
FONT="/usr/share/consolefonts/Unifont-APL8x16.psf.gz"
```
