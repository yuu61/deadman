# 詳細設定リファレンス

このドキュメントでは、`deadman` の設定ファイルで指定可能な各属性や中継モードの詳細、および表示設定について解説します。

## 属性の詳細

- **`source=...`**
  プローブの送信元（送信元 IP アドレス、または `source=eth0` のようなインターフェース名）を指定します。直接 ICMP・`nexthop`・ssh/netns/vrf 中継で有効です。インターフェース名を使えるのは直接 ICMP・`nexthop`（Linux）と Linux 上の ssh/netns/vrf 中継のみです（macOS/BSD の中継先では IP アドレスを指定してください）。

- **`verify=on|off`** （routeros / quic モード）
  TLS 証明書検証の有無を指定します（`true|false` 等も可）。
  - routeros モード: 既定**有効**。自己署名証明書の機器向けに無効化できます。
  - quic モード: 既定**無効**。IP アドレスを直接対象にすることが多く、証明書検査が失敗しやすいためです。

- **`port=` / `alpn=` / `sni=`** （quic モード）
  ダイヤル先ポート（既定 `443`）、ALPN（既定 `h3`）、TLS の SNI（`ServerName`）を指定します。`sni` を省略するとアドレス欄のホスト名が使われます。検証無効でも SNI は送出されるため、実在の h3 フロントを IP で対象にする場合は `sni=` の指定が必要になることがあります。

- **`resolve_family=ipv4|ipv6`**
  ホスト名の解決を A / AAAA レコードに固定し、dual-stack なホスト名を IPv4 / IPv6 で別々に監視します。
  - 直接 ICMP と `via=quic` でのみ有効です。
  - ホスト名が同一ファミリー内に複数アドレスを持つ場合、RFC 6724 で並べ替えた先頭の 1 アドレスだけがプローブ対象となります。特定の1台を継続監視したい場合は IP アドレスを直接指定してください。

- **`nexthop=GWIP`**
  直接 ICMP プローブを指定ゲートウェイ経由で強制送出し、特定経路の到達性を監視します。ゲートウェイは on-link である必要があります（Linux + root/CAP_NET_RAW 必須）。

## 表示設定（ディレクティブ）

設定ファイル内に以下の行（ディレクティブ）を含めることで、起動時の表示状態をコントロールできます。

### 段組み（左右分割）表示: `split`
```text
split 2
```
端末の横幅に余裕がある場合、一覧を複数列に折り返して表示します。列を増やすと RTT バーは短くなります。要求した列数が端末幅に収まらない場合は自動で減らされます。

### 列（カラム）の表示: `columns`
```text
columns ADDRESS=off MIN=off MAX=off VIA=on
```
`RESULT` 以外の各列の表示・非表示を切り替えます。`VIA` 列は、実際に使われた取得方法（`direct`, `nexthop`, `ssh`, `quic` 等）を表示します。

### 表示精度（RTTバーと統計値）: `scale` / `precision`
```text
scale 5
precision ms.1
```
- `scale`: RTT バー1段あたりの ms 単位の幅（既定 10、小数可）。CLI オプション `-s` が優先されます。
- `precision`: 統計列（RTT / AVG / MIN / MAX / JIT）の数値表記（`ms`, `ms.1`, `ms.2`, `ms.3`）。桁を増やすほどサブミリ秒の差が見えます。

### RESULT バーの表示文字: `glyph`
```text
glyph digit
```
成功したプローブを RESULT バーに描く文字の組を指定します（既定 `auto`）。CLI オプション `-g` が優先され、実行中は `b` キーで block → ascii → digit と切り替えられます。

| 値 | 表示 | 段階 |
| --- | --- | --- |
| `block` | `▁▂▃▄▅▆▇█` | 8 段階。帯域 i は scale×i 以上 scale×(i+1) 未満、`█` は scale×7 以上 |
| `ascii` | `_.-=+*#@` | `block` と同じ 8 段階・同じ閾値で、文字だけを ASCII にしたもの |
| `digit` | `0`〜`9` | 10 段階。数字 d は scale×d 以上 scale×(d+1) 未満、`9` は scale×9 以上（scale 10 なら `3` は 30〜39ms） |
| `auto` | `block` か `ascii` | 起動時に端末を判定し、ブロック文字を表示できなければ `ascii` を使う |

対数表示（`l` キー）では、各段階が等比の帯域になります（`digit` なら 9 帯域 + 超過）。失敗の `X` / `t` / `s` はどの組でも同じです。
文字の色も同じ段階で決まり、最も速い段階が緑、最も遅い段階が赤になります（[RESULT バーの色](platform_and_font.md#result-バーの色)）。

`auto` は次の場合に `ascii` を選びます。どちらにも当てはまらなければ `block` です。
- ロケール（`LC_ALL` → `LC_CTYPE` → `LANG` のうち最初に設定されている値）が UTF-8 でない（例: `C`, `ja_JP.eucJP`）。何も設定されていない場合と Windows では判定しません。
- Linux の仮想コンソール（tty1 等）で実行しており、読み込まれているコンソールフォントに `▁`〜`█` のいずれかが無い（カーネルからフォントの Unicode 表を取得して確認します。Debian 系の既定フォント Lat15 が該当）。

SSH や端末エミュレータ、tmux、fbterm などの疑似端末（pty）では、実際の描画は接続元の端末のフォントが行うため判定できず、`block` のままになります。**Linux コンソールから SSH で別ホストの deadman を開く**場合は、`-g ascii` か `glyph ascii` を指定してください。
表示文字は `scale` / `precision` と同じく実行中の設定として扱い、設定の再読み込み（`R` / SIGHUP）では変更されません。
